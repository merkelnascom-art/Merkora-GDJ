# Project team and public access Implementation Plan

> **For agentic workers:** Use the host's available task-by-task implementation workflow. Steps use checkbox syntax for tracking.

**Goal:** Deliver reusable owner-managed team access for every generated MerKora application while keeping published public pages, especially Asho Sweet's catalogue, accessible without an account.

**Architecture:** Add project-scoped memberships and invitation records enforced by Supabase RLS. Server-side Supabase Edge Functions send invitations and activate membership only for a verified matching email. Generated storefront and generic workspaces distinguish public visitors, customers, owners, and invited staff.

**Tech Stack:** Next.js 16, React 19, TypeScript, Supabase Auth/Postgres RLS/Storage/Edge Functions, Deno, Vitest.

## Global Constraints

- Public visitors can browse published storefront pages and active products without signing in.
- Asho Sweet starts empty and unpublished; only the owner adds real creations, photos, descriptions, and prices and chooses when to publish.
- Customer accounts are optional for browsing and guest orders; signed-in customers can access only their own order/request history and private reference photos.
- Only the project owner can invite workers or collaborators. Staff access is invitation-only.
- The owner chooses which modules each collaborator can access and whether each grant is view-only or edit.
- Authorization is enforced server-side and by RLS, never by hiding controls or trusting user-editable metadata.
- Preserve all existing business data. All schema changes are additive.
- Never expose a Supabase service-role key in generated browser code.
- No merge, production deployment, destructive reset, or paid Vercel Sandbox run without separate explicit approval.

- Recommended invitation expiry is seven days. This expiry duration must be confirmed before implementing automatic expiration.
